# v0.9 手机号登录与注册（2026-10-27）

## 已实现
- 复用小岛背景的 Web/H5 登录界面，桌面与 390 × 844 竖屏适配。
- +86 手机号 + 六位验证码；首次验证自动注册，重复验证登录同一账号；游客可直接进入。
- 游戏左上角账号入口、退出登录、手动带入游客存档（只复制空目标，不覆盖账号已有存档，不删除游客数据）。
- 服务端 SQLite 持久化账号及会话；HttpOnly / SameSite=Strict Cookie；正式模式增加 Secure。
- 5 分钟验证码、60 秒重发限制、单码最多 5 次错误、一次性使用；手机号与 IP 请求限额。
- 游戏启动等待身份确定；账号与游客分别存档。学习进度仍在浏览器本机，不是云同步。

## 当前运行方式
`npm run serve` → http://127.0.0.1:7456/

默认 **demo**：不会发送真实短信，页面明确展示演示码。演示不证明手机号所有权，不能用于正式用户身份认证。当前账号库仅供本地体验。

数据在忽略目录 `local/auth/`，包含 secret、auth-demo.sqlite。手机号仅保存 HMAC 查找值及掩码；验证码保存 HMAC；会话保存 token 的 HMAC。备份数据库时同时备份 secret，不要提交这些文件。

使用 Node 22.22.0 的内置 node:sqlite（当前运行时提示 experimental），无新增 npm 依赖。

## 真实短信接入边界
尚未配置短信服务商、已审核签名/模板，也未发送或验收真实短信。无需把密钥交给聊天或前端。

服务端环境变量：
- `AUTH_MODE=live`
- `AUTH_PUBLIC_ORIGIN=https://实际站点域名`（要求 HTTPS；反向代理保留 Host）
- `SMS_ADAPTER_PATH=/本机私有目录/短信适配器.cjs`
- `AUTH_DATA_DIR=/本机私有数据目录`
- `STARISLE_PORT=7456`（服务仅监听 127.0.0.1）

适配器导出异步函数 `module.exports = async ({phone, code, expiresInSeconds}) => { ... }`，调用所选服务商 SDK，检查其业务响应是否成功，失败必须抛错。密钥、签名和模板从服务端环境读取，不记录手机号或验证码。缺少适配器或 HTTPS 时 live 模式拒绝启动。live 与 demo 使用不同数据库和账号 ID 前缀；演示进度不会冒充正式账号。

服务端接口：GET /api/auth/config、GET /api/auth/me、POST /api/auth/code、POST /api/auth/verify、POST /api/auth/logout。POST 要求同源 Origin、JSON，限制请求大小。后续上线仍需结合实际服务商、代理与风控验收；本轮无外网部署。

## 短信宝接入更新（2026-10-27）
用户授权使用已登录的短信宝后台完成配置。已读取现有 API Key，直接保存到忽略目录 `local/auth/smsbao.json`，权限 0600；无密钥写入前端、文档或日志。保留所有原业务模板、签名和密钥，没有重置密钥。

采用后台已审核原文：`【来一桔文化】您的验证码是{code}。如非本人操作，请忽略本短信`。该签名会出现在收件短信中，尚未申请星屿专属签名。后台模板列表显示多条已审核记录，总览模板计数显示 0，与列表不一致，采用实际列表记录。

`server/providers/smsbao.cjs` 依据官方国内短信 API，固定 HTTPS 发送端点，URL 编码参数，只把纯文本返回码 0 认定为提交成功；10 秒超时，禁止重定向，不自动重发，异常不包含手机号、验证码、密钥或完整请求 URL。官方文档：https://user.smsbao.com/docs/developer/domestic-sms-api.html

`tools/serve.cjs` 自动加载本机私有配置，enabled=true 默认启用 live；AUTH_MODE=demo 可显式切回演示。正式模式仍禁止外部 HTTP，仅允许本机回环 HTTP 联调（服务绑定 127.0.0.1）；HTTPS 环境使用 Secure Cookie。未做外网部署。

已执行适配器模拟测试与全部游戏/账号回归测试。模拟测试不会发送短信。尚未收到用户提供的测试号码，因此未发送真实测试短信、未确认到达手机；API 提交成功也不能替代真实送达验收。

### 真实发送联调
2026-10-27 用户提供本人测试号码后，通过游戏 `/api/auth/code` 向尾号 0682 发送一次验证码。接口返回 HTTP 200、mode=live、cooldown=60，意味着短信宝已接受提交；未输出或读取验证码。手机实际送达和输入验证码完成登录仍待用户验证。首次执行审批超时，命令未启动；随后一次执行成功，无重复发送。

用户收到短信并提供验证码后，服务端验证返回 HTTP 200、created=true、mode=live，尾号 0682 的正式账号创建成功。真实短信收码→验证码核验→注册闭环通过。此次通过接口验证，未将会话注入用户浏览器；网页登录仍需在页面获取并输入新验证码。未将验证码或会话密钥写入文档。

# 星屿学园后台架构与扩展指南

状态：2026-10-28，本地实现；未部署到生产。

## 运行与入口

- `npm install`（Node.js 22.13+，使用内置 SQLite）。
- `npm run serve`，后台路径 `/admin`，游戏路径 `/`。
- 首次启动自动生成 `local/admin/bootstrap.txt`，账号 `admin`，随机初始密码；文件权限 0600。首次登录后在“管理员与权限”修改密码，初始凭据文件随之移除。
- 不存在硬编码默认密码。管理员会话与游戏短信登录完全分离。
- 自定义 `STARISLE_PORT`、`AUTH_PUBLIC_ORIGIN`、`ADMIN_DATA_DIR`。反向代理必须保留正确 Host，外部使用 HTTPS origin；默认只监听本机。
- 本次预览使用 7460 端口；隔离验收使用 7461 和 `/tmp/starisle-admin-qa-20261028`，不接触真实短信与云存档。

## 边界与职责

| 层 | 文件 | 职责 |
|---|---|---|
| HTTP 装配 | `tools/serve.cjs` | 管理、内容、认证、存档路由与静态文件 |
| 管理 API | `server/admin.cjs` | 管理会话、权限、来源检查、请求大小、接口编排 |
| 内容契约 | `server/content/schema.cjs` | 玩法注册表、参数校验、引用完整性、发布包编译 |
| 内容仓储 | `server/content/store.cjs` | 事务、草稿版本、稳定身份、不可变发布快照、审计 |
| 导入适配器 | `server/content/import.cjs` | Excel 模板、解压限制、逐行校验、预览 |
| 后台界面 | `web/admin/` | shell / UI 通用组件 / 内容工作区 / 账号工作区 |
| 游戏内容适配 | `assets/scripts/adventure/ContentRuntime.ts` | 兼容性检查、缓存、原子替换、更新调度 |
| 游戏展示与判定 | `Adventure.ts`、`Puzzle.ts` | 现有 Cocos 玩法，不承担管理权限和发布 |
| 游戏进度 | `Progress.ts` | 保留历史完成记录、勋章和稳定章节定位 |

后台业务数据与运行时内容包之间有编译边界。游戏只获取已发布包；草稿接口必须具有 owner/editor 会话。新学科不再需要修改 Subject 联合类型或固定数量的菜单。学科目录、章节选择均支持分页，暂无关卡的年级显示空状态。

## 内容模型

- **Subject**：永久 `id`、名称、排序、主题、状态。
- **Question**：永久 `id`、学科、年级、知识点、状态、玩法数据 `data`。
- **Chapter**：永久 `id`、学科、年级、主题、教材对应、状态、`bindings`。
- **Binding**：永久关卡 `id` + `questionId`。题目可以复用，玩家进度对应关卡身份。
- **Release**：单调递增的发布编号、内容契约版本、模块版本要求、完整快照、审计元数据。

当前仓储使用一个 SQLite 文件中的不同表：`draft`、`releases`、`identities`、`audit`、`admins`、`admin_sessions`、`settings`、`schema_migrations`。草稿/快照是版本化 JSON 文档，适合现阶段内容量和单服务部署；这是明确的阶段性选择，不是已实现的多实例内容集群。

当前只支持一个全局草稿，保存时使用 revision 比较并交换；并发修改返回 409，界面保留编辑弹窗，需刷新后重新编辑。后续多人高频编辑或内容量增大时，在仓储层迁移到 MySQL 独立实体表和逐实体 revision，并把发布包放对象存储/CDN。HTTP 与游戏端发布契约无需随之更换。当前 JSON 请求上限 4 MB，不能将声明的实体数量上限视作容量承诺。

## 发布与进度保护

1. 编辑/导入只写草稿；导入预览 token 绑定管理员与草稿版本，15 分钟失效。
2. 发布执行全量校验、检查已发布 ID 的绑定关系，写入不可变快照并在同一事务切换当前版本。
3. 已发布章节不可改变学科/年级；已发布关卡不可换题或跨章移动。通过复制创建新身份。
4. 发布记录回退会生成新发布编号，不覆盖旧版本；草稿不变，玩家存档不回退。
5. 历史身份表累计所有已发布关卡、章节与学科。回退或下架后仍随发布包提供给客户端，完成记录和勋章继续有效。
6. 新存档同时保存 `chapterId`，兼容旧的章节索引。排序变化后按稳定 ID 找到原章节。
7. 积分仍由游戏规则计算，后台只显示关卡基础积分/经验，不擅自修改积分，也不把它当竞赛可信成绩。

游戏启动时加载最新兼容包；地图页面每 30 秒检查版本，重新进入地图时也可触发到期检查。只有请求返回时仍处于地图才替换内容，进行中的题目和试炼不被换掉。失败则保留当前内容；下一次启动先使用上次兼容缓存，缓存不可用时使用内置课程。全新玩法模块必须先部署兼容客户端，否则旧客户端拒绝整个不兼容包并使用原有内容。

## 扩展学科、内容和玩法

### 添加新学科（无需改代码）

后台“学科管理”新增 → 创建或导入题目 → “关卡与章节”新建章节并添加题目 → 试玩 → 负责人发布。可先只做一个年级，其余年级显示待上线。当前年级范围为小学 1～6 年级。

### 添加现有玩法内容（无需改代码）

七类玩法：`choice`、`number`、`sentence`、`cargo`、`groups`、`tiles`、`listen`。Excel 为 `.xlsx`，一次最多 2000 行、2 MB；可解压内容上限 12 MB。文件中不允许公式；错误定位到行。所有行通过后才允许提交，重传相同题目编号走更新。未提供自动 Word/PDF 识题。

当前选择/听音玩法最多三个选项，与现有 Cocos 布局一致；扩展为更多选项要同步调整游戏布局和校验规则。听音内容目前使用已随游戏打包的语音，尚未实现新音频/图片的上传与分发。

### 添加全新玩法（需要开发）

1. 在游戏 `Mechanic` 契约中声明类型，在 `Puzzle` 实现判定，在游戏展示层实现交互。
2. 在服务端模块注册表添加 ID、版本、字段与校验规则；校验应覆盖可解性和客户端显示上限。
3. 在题目编辑器添加配置字段，在导入适配器定义映射；需要时提升内容契约/模块版本。
4. 增加判定、发布、存档兼容测试；先部署兼容客户端，再发布引用新玩法的内容。

### 添加新的业务模块

课程内容与账号、发布、权限分开。新的业务模块应拥有自己的服务、数据表/迁移和后台工作区，复用管理员认证与审计；不要将功能代码、任意脚本或未知玩法 JSON 当作“模块上传”。例如试卷模块有独立试题结构，不应强行塞进操作型关卡参数。当前新增的综合试炼源码和存档字段保持兼容；其试卷编辑尚未纳入本后台。

## 用户与权限

- owner：编辑、导入、试玩、发布、回退、用户管理、管理员创建、审计。
- editor：内容与预览；不能发布、回退或读取用户。
- support：用户与只读云档案、冻结/解冻；不能修改课程。
- 游戏用户列表以认证用户库为准，包含尚无云存档的注册用户。历史账号原来没有注册时间时明确标记，不伪造时间。
- 冻结用户撤销现有会话，禁止重新登录与云存档访问；无法控制已下载的离线游戏。
- 账号目前仍是一登录用户对应一份进度；尚未实现一家庭多玩家档案、换绑、用户删除或存档恢复操作。
- MySQL 云存储连接配置不存在时，管理页面明确显示“未配置云存储”，不把本机游客数据冒充云数据。

## 运维与维护

- `local/admin/` 包含内容库和管理身份；`local/auth/` 包含游戏登录身份，既有 MySQL 保存玩家进度。不要把这些目录提交到版本库。
- SQLite 使用 WAL；备份应停服务后复制整个目录，或使用 SQLite 一致性备份 API，不能在线只复制主数据库文件。
- 发布回退只处理内容，不代替数据库备份。上线前需要将上述目录放持久存储并配置备份策略。
- seed.json 是可审查的首次迁移基线；已有内容库启动后不会被种子覆盖。`node tools/export-content.cjs` 仅供开发时显式重新导出内置内容，不应在每次服务启动时运行。
- 依赖锁文件固定，ExcelJS 的 UUID 依赖覆盖到 11.1.1+；本次安装审计为 0 项漏洞。

## 验证

- `npm test`：原有关卡、存档、认证、短信适配器、云同步回归。
- `node tools/test-content-runtime.cjs`（先运行 npm test 生成临时编译结果）：新增学科、内容回退保留奖励、版本不兼容原子拒绝、重排章节定位。
- `npm run test:admin`：临时本地 HTTP 环境验证角色、CSRF、CAS、发布、导入、冻结、审计及重启持久化。
- Cocos TypeScript noEmit 与 `npm run build:web`。
- 浏览器隔离环境新增学科 → 新题 → 新章节 → 真实 Cocos 试玩 → 发布；验证结果见 `qa/admin-*.png` 和 `qa/test-admin-regression.log`。

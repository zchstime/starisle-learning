# 开发架构与边界

## 当前实现

Cocos Canvas 场景 → StarIsle 场景控制器 → MathPuzzle 数学操作域模型 / GameSession 进度域模型 → SavePort 存储接口 → LocalSave。

所有工作台与按钮都由 Cocos 节点、Graphics、Sprite、Label 和事件系统实现，没有 DOM 学习页依赖。美术资源通过 resources 加载。向导移动、粒子和通关反馈使用 Tween。TypeScript 的纯领域层可以脱离引擎验证。

关卡顺序为加法、减法、等组乘法，再进行迁移试炼。操作状态与答题判定分开：未完成换十、拆捆配送或等组操作，不能只输入正确数字跳过关卡。通关星章与试炼分数分开记录。提示不扣体力、不扣永久成长。

当前 MathPuzzle 实现的是三个明确的教学模板；新数字参数尚需进一步抽象。GameSession 为离线游戏服务，不可直接作为线上高风险测评可信评分端。

## 下一步可扩展方向

1. 将 operands / groupCount / groupSize / exchangeBase 等抽取为配置，增加内容包校验和教研预览工具。
2. 把 StarIsle 视图拆为 MapView、BaseTenView、EqualGroupsView、TrialView；现在的领域层已独立。
3. 新增练习生成器，控制进退位条件；保存题目种子与版本，区分首次、提示后和复测表现。
4. 新增带版本的 HTTP 服务与账号，服务端验证作答和奖励，使用幂等请求及断网队列；本地 SavePort 替换为同步适配器。
5. 为平台登录、分享、音频和存储单独建立平台接口。Cocos 可输出多平台，不意味着支付、登录和性能可以免验证。
6. 手机竖屏采用工作台/答案区上下排布。目前首版为横屏等比适配，并在 Web 竖屏显示旋转建议。

## 验证原则

数块守恒：换十前后总数相同；配送前库存 = 剩余 + 已送；花盆不超过目标。延迟/重复点击不产生重复奖励。存档损坏不崩溃，非连续进度不能越级解锁。测评结果重新计算，不信任存储的 score。

本版本不声称游戏能提高成绩；需要针对目标儿童验证理解、负担与延迟迁移效果。

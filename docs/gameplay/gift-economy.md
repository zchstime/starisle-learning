# 星光礼物屋：积分与虚拟礼物

2026-11-01。本轮在 Cocos 主线的观星花园和趣味练习中实现，尚未发布线上。

## 让收藏成为回来的理由

循环是“完成学习 → 攒下积分 → 自己选礼物 → 布置自己的花园”。吸引力来自审美、选择和归属，不来自抽奖、限时清空或连续签到。兑换只是装饰，不改变题目难度、学习机会或成绩。

保持一种可消费积分，避免金币、钻石、票券增加理解成本。经验仍负责等级，晨露仍记录照顾，两者不花费。兑换扣除可用积分，不减少累计积分或等级。

## 已实现的兑换路径

- 礼物屋分“花园礼物”和“称号徽记”，每页三件，装饰使用真实生成的透明 PNG，不是符号占位。
- 可随时打开大图预览；显示用途、价格、当前余额和兑换后余额。
- 不足时可设为心愿或取消；余额足够时仍可先设心愿，不强迫消费。心愿只显示差额，无截止期限。
- 独立的“确认兑换”按钮扣分；重复点击和再次购买不会重复扣费。每款只收藏一件。
- 已有装饰进入“礼物角”，三个位置可以摆放、交换或收回。所有布置免费，收回不退款也不失去所有权。
- 花园礼物不会覆盖首页称号；旧称号继续可佩戴。
- 收藏进度只描述拥有数量，没有凑齐奖励或催促。

## 美术与资源

使用内置 image_gen 分别生成三张透明 PNG，统一薄荷绿、奶油白、柔紫、暖金的圆润玩具质感。图片为 1254×1254 RGBA，保留原始透明度，配套 Cocos image 元数据。运行时按需加载，离开页面后不向销毁节点插图；加载失败显示说明，并允许重新进入重试。

资源：assets/resources/art/gifts/。完整生成提示词：art-source/gifts-v1/prompts.json。没有改写旧美术。

## 存档与经济边界

所有权沿用 gifts 数组，并集同步；消费由固定目录价格计算。旧版离线多端并发兑换如果总额超预算，仍按既有固定商品顺序保留可负担物品，其余需要重新选择；不保证离线并发交易的最终成交。放置布局使用 giftDisplay 的时间戳冲突规则，合并后过滤未拥有和重复物品。心愿沿用本地偏好覆盖策略。

这是无付费的客户端装饰经济，不能直接用于现金、交易或可信资产。若未来引入充值或转赠，须先替换成服务端订单及事务账本。

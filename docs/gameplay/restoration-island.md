# 星屿修复岛 · 首个可玩闭环

2026-11-01。本地开发版本，未部署生产。面向二年级数学的原创练习，不宣称完整教材覆盖或已经验证学习效果。

## 本轮决策

采用“知识操作 → 设施修复 → 获得工具 → 处理新条件”的主循环。先证明一座岛可玩，再扩展课程、多人合作和内容配置。持续可玩性仍需儿童真实试玩验证，当前不称为最终最佳方案。

保留原有课程地图、期末试炼和观星花园。修复岛是新增的 Cocos 玩法，不用网页表单替代游戏，不把修复任务算入教材关卡或期末考试解锁条件。

## 入口与体验

二年级数学地图左上角“星屿修复 · 新冒险”；其他学科可通过探索目录中的“星屿修复 · 二年级数学”进入，不改动当前学科和年级。

1. 花园与水渠均可先玩，观星台需要两处都修好。
2. 花园：把 12 只星萤按每坛 3 只安排；修复后提供六格星灯，用于后续运输。
3. 水渠：用 1、3、5 桶水箱，在最多 4 箱的限制下运来 12 桶水；修复后提供一次安排 3 只星萤的工具。
4. 观星台：沿修好的水渠，用最多 3 块物资提供 18 格能量；需要花园提供的六格星灯。完成后开放天气航线。
5. 晴天需要 21 格、最多 4 块；有风需要 15 格、最多 3 块。天气由孩子选择，不使用实时天气或随机惩罚。
6. 每座设施共 3 项任务，总计 9 项。包含修复、变式与开放组合。花坛创作允许多种平均分法，最新成功布局直接显示在修复岛花园上。
7. 原有观星花园仍支持自由布置。首次完成修复岛任务参与其树苗成长；不需要做完所有任务才能离开。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `Restoration.ts` | 手工任务配置、设施依赖、可接受解、操作状态与有界存档清洗 |
| `RestorationView.ts` | Cocos 分组/装载操作、设施状态、工具入口、完成反馈与探索记录 |
| `Progress.ts` | 账号存档、唯一任务奖励、照顾记录、花园成长；主线与修复进度分开 |
| `web/auth/cloud.js` | 按任务合并首次/最近完成证据和最新操作草稿 |
| `server/saves.cjs` | 新字段的结构、任务 ID、数量与类型限制；仍沿用既有鉴权与冲突协议 |

任务包含知识技能标识、版本内稳定 ID、先修条件、目标、规则、提示和世界变化说明。当前规则为本地手工配置，尚未开放后台编辑。未来改变任务语义或判定条件时应新增任务 ID 或设计迁移，不能把旧记录直接解释成新版任务的完成证据。

## 存档与奖励

在现有 `starisle.adventure.v3` 中新增 `island.version=1`，不重置旧存档。每个任务最多保留首次/最近一次成功的证据及一份草稿，避免无限增长。

- 每次摆放、撤回、提示、提交都会保存草稿；返回菜单、重新摆放、刷新不会抹去该轮的错误提交次数和提示使用。
- “首次尝试”指本轮第一次提交；提交前的摆放调整不算错误。记录仅描述此次作答，不表示掌握率或隔日迁移验证。
- 完成后才能开始新一轮。首次完成每个任务仍按现有规则计 100 积分、30 经验；重复通关不重复加分。每累计 3 个唯一任务产生一棵树苗，与原有主线和趣味任务合计。
- 完成/复习参与现有每日照顾规则，同任务同日不重复计入，每日显示最多 3 份晨露。不引入新货币、倒计时或断签损失。
- 云合并取最早首次证据、最新回放证据和最新草稿；完成草稿作为结束标记，避免较旧离线草稿重新打开已结束的任务。同时间用固定内容顺序决胜。
- 多设备同时改同一任务时只保留其中一份最新草稿，不承诺合并两种摆放。完成记录按任务合并，奖励由唯一完成 ID 推导。
- 保存失败明确提示并可重试，不将未成功保存显示成已保存。云端同步仍走原有账号流程，本轮没有使用真实用户云存档做写入测试。
